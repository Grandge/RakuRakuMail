## 最初にやること: 実機確認で見つかった不具合2件

**どちらも 2026-09-01 のログイン確認で判明したものです。次回の冒頭で直してください。**

### (1) ログアウト時の revoke をやめる

**症状:** ログアウト → 再ログインで、1回目が失敗し2回目で成功する。

**原因:** `src/auth/session.ts` の `signOut()` が `revokeToken()` を呼んでいます。これが許可を中途半端に取り消すため、再ログイン時に Google が「**らくらくメール が Google アカウントへの追加アクセスを求めています**」「すでに一部のアクセス権限を付与されています」という増分同意の画面を出し、1回目はスコープが揃わずアプリ側が `scope_denied` と判断します。

**修正:** `signOut()` から `revokeToken()` の呼び出しを外し、メモリ上のトークンを捨てるだけにしてください。理由は3つです。

1. トークンはメモリ上にしかありません（D-54）。捨てた時点でこのアプリからは使えず、ログアウトとして成立します
2. revoke すると次回ログインで同意画面をやり直すことになり、高齢者やITが苦手な人が使う前提（NFR-01）では重すぎます
3. `void signOut()` は投げっぱなしなので、revoke の完了前に再ログインすると競合します

`revokeToken()` 自体は残し、S-07 設定画面の「この端末のデータを消す」から `db.clearAll()` と一緒に呼びます。`clearAll()` について決めたのと同じ整理です。

### (2) ログイン画面の案内文が実際の Google の画面と食い違っている

**症状:** `src/ui/screens/LoginScreen.tsx` の案内はこうなっています。

1. 画面の左下にある「**詳細**」を押します
2. 下に出てくる「らくらくメール（**安全ではないページ**）に移動」を押します

**しかし実際の警告画面にその表示はありません。** Google が画面を作り直したようで、現在はこうなっています。

- 見出し: 「このアプリは Google で確認されていません」
- 本文: 「現在テスト中のアプリへのアクセスが許可されました。招待元のデベロッパーを信頼できる場合のみ、続行してください。」
- 左下に「**続行**」（小さいリンク）、右下に「**安全なページに戻る**」（目立つ青いボタン）

**修正:** 案内文を実際の画面に合わせてください。

1. 左下の「**続行**」を押します
2. 許可の確認画面が出たら「**続行**」を押します

**目立つ青いボタン「安全なページに戻る」を押すと進めない**ことも書き添えてください。この案内は NFR-01 と D-08 のために置いたもので、実際と食い違っていると意味がありません。あわせて `要件定義書 2.5` の記述も実際の画面に合わせてください。

## 設計上の約束（崩さないでください）

```
ui/  ──▶  domain/  ──▶  gmail/  ──▶  auth/
              │            │
              ▼            ▼
           store/       mail/
```

- `mail/` は **Gmail API を一切知りません。** 文字列とバイト列だけを扱う純粋関数にして単体テストで固めています
- `gmail/` は Gmail API の形だけを知り、らくらくメールの都合（目印・独自ヘッダ）を知りません
- `ui/` から `fetch` を書かないでください
- トークンは `auth/session.ts` のメモリ上のみ。`localStorage` にも IndexedDB にも書きません（D-54）
- 本文は `dangerouslySetInnerHTML` を使わず、テキストとして表示します（D-23 / 6.2）
- **ログアウトでは端末の保存データを消しません。** 消去は S-07 設定画面の「この端末のデータを消す」から、確認画面を挟んで行う仕様です（6.2 / 5.4 / D-55）
